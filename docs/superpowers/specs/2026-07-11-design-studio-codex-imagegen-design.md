# Design Studio Codex ImageGen Design

## Goal

관리자 디자인 스튜디오에서 팝업, 배너, 일반 이미지 유형과 프롬프트를 선택하면 기존 이츠비의 로그인된 Codex 런타임이 ImageGen 스킬로 이미지를 만들고, 결과를 편집 캔버스에 즉시 삽입한다.

## Approved approach

- 별도 OpenAI API 키를 추가하지 않는다.
- 운영 서버의 `codex exec` 로그인과 내장 `imagegen` 스킬을 재사용한다.
- 이미지 생성은 오래 걸릴 수 있으므로 요청 생성과 상태 조회를 분리한 비동기 작업으로 처리한다.
- 생성 원본은 Codex 내부 경로에 남기지 않고 `uploads/design-studio/ai/`로 복사해 관리자 정적 URL로 제공한다.
- 생성 이미지는 단일 배경 레이어로 Fabric 캔버스에 넣고 문구, 버튼, 로고는 기존 편집 기능으로 수정한다.

## UX

- 도구 영역 상단에 `AI 이미지 만들기` 패널을 둔다.
- 유형은 `배너`, `팝업`, `일반 이미지`로 명시적으로 선택한다.
- 일반 이미지는 정사각형, 가로형, 세로형 프리셋을 제공한다.
- 생성 중에는 단계 메시지와 경과 시간을 표시하고 중복 요청을 막는다.
- 완료되면 미리보기와 `캔버스에 적용` 버튼을 표시하며 기본 동작은 자동 적용이다.
- 실패하면 원인을 숨기지 않고 재시도 버튼을 제공한다.

## Server flow

1. 인증된 시스템 관리자가 생성 요청을 보낸다.
2. 서버가 프롬프트 길이, 유형, 크기를 검증하고 메모리 작업 레코드를 만든다.
3. 서버가 현재 프로세스와 분리해 Codex CLI를 실행한다.
4. Codex JSONL 출력에서 thread id와 최종 메시지를 읽고, 해당 thread의 최신 생성 이미지를 찾는다.
5. 이미지를 공개 업로드 폴더로 복사하고 작업을 완료 상태로 바꾼다.
6. 브라우저가 상태를 폴링해 이미지 URL을 받고 Fabric 캔버스에 삽입한다.

## Security and operations

- 시스템 관리자 전용 API로 제한한다.
- 프롬프트는 1200자, 동시 작업은 서버 전체 1개로 제한한다.
- Codex 홈은 서버 프로세스가 직접 소유하지 않고, 권한이 분리된 실행 래퍼를 사용한다.
- 쉘 문자열 조합 없이 `execFile` 인자로 전달한다.
- 5분 제한시간과 출력 버퍼 제한을 둔다.
- 생성 결과 파일만 업로드 폴더로 복사하며 임의 경로 반환을 신뢰하지 않는다.

## Verification

- 서버 단위 테스트로 요청 검증, 상태 전이, 이미지 경로 탐색을 확인한다.
- 관리자 모듈 테스트로 유형/크기 매핑과 상태 표시를 확인한다.
- 운영에서 테스트 프롬프트 한 건을 생성하고 공개 URL, 캔버스 적용, 서비스 상태를 확인한다.
