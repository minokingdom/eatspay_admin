# 관리자 계좌 증빙 OCR 검증 설계

## 목적

관리자가 계좌 등록 확인 모달에서 증빙 사진의 계좌번호를 확대해 직접 옮겨 읽는 부담을 줄인다. OCR은 검증 보조 도구이며 계좌 승인을 자동으로 수행하지 않는다.

## 범위

- 운영 서버 내부의 Tesseract OCR 사용
- 관리자 인증이 필요한 계좌 증빙 OCR API 추가
- 저장된 계좌 증빙 이미지 한 장만 OCR 대상으로 허용
- OCR 숫자 후보와 등록 계좌번호 비교
- 관리자 모달에 일치, 불일치, 인식 실패 결과 표시
- 다른 PC와 모바일 브라우저에서도 별도 설치 없이 사용

## 제외 범위

- OCR 결과에 따른 자동 승인 또는 자동 반려
- 외부 OCR API로 증빙 이미지 전송
- OCR 원문이나 전체 계좌번호의 서버 로그 기록
- PDF 등 이미지가 아닌 첨부 파일 OCR
- OCR 결과의 데이터베이스 영구 저장

## 서버 구조

### OCR 실행 모듈

`lib/account-proof-ocr.js`가 다음 책임을 가진다.

1. 계좌번호를 숫자로 정규화한다.
2. OCR 텍스트에서 8~20자리 숫자 후보를 추출한다.
3. 등록번호와 정확히 일치하는 후보를 우선 선택한다.
4. 불일치일 때 자리 수와 문자 차이가 가장 적은 후보를 반환한다.
5. Tesseract 프로세스를 제한 시간 안에서 실행하고 종료한다.

Tesseract는 외부 셸 문자열을 조합하지 않고 인자 배열로 실행한다. 언어는 숫자 인식이 중심이므로 기본 `eng`를 사용하고 숫자 화이트리스트를 적용한다.

### API

`POST /api/admin/accounts/proof-ocr`

요청:

```json
{
  "documentUrl": "/uploads/<file-key>",
  "accountNo": "56216975432139"
}
```

보안 및 검증:

- `authenticateAdmin` 필수
- `documentUrl`은 `/uploads/` 아래의 안전한 파일 키만 허용
- 실제 파일 경로가 업로드 디렉터리 밖으로 벗어나지 않는지 확인
- 이미지 확장자만 허용
- 등록 계좌번호는 숫자 8~20자리만 허용
- OCR 프로세스 제한 시간 20초
- 동시 실행 수를 프로세스당 1개로 제한
- 실패 시 내부 경로나 OCR 원문 전체를 응답하지 않음

응답 예시:

```json
{
  "status": "matched",
  "registeredAccountNo": "56216975432139",
  "recognizedAccountNo": "56216975432139",
  "candidates": ["56216975432139"]
}
```

`status`는 `matched`, `mismatched`, `not_found` 중 하나다.

## 관리자 UI

계좌 검증 기준 카드에 `계좌번호 자동 인식` 버튼을 추가한다. 클릭 시 버튼을 비활성화하고 `증빙에서 숫자를 읽는 중…` 상태를 표시한다.

결과 영역:

- `matched`: 초록색, `계좌번호가 일치합니다.`
- `mismatched`: 빨간색, 등록번호와 인식번호를 고정폭 글꼴로 나란히 표시하고 다른 자리 강조
- `not_found`: 주황색, `계좌번호를 인식하지 못했습니다. 증빙을 직접 확인하세요.`
- API 실패: 재시도 안내와 기존 `증빙 크게 보기` 유지

OCR 결과가 어떠하든 기존 `검증` 버튼의 동작은 바뀌지 않는다.

## 개인정보와 운영

- 이미지는 운영 서버 밖으로 전송하지 않는다.
- OCR 결과는 현재 모달에만 표시하며 DB에 저장하지 않는다.
- 로그에는 관리자 ID, 성공 여부, 처리 시간만 기록할 수 있고 계좌번호와 OCR 원문은 기록하지 않는다.
- 운영 서버에 `tesseract-ocr` 패키지를 설치하고 배포 전후 서비스 상태를 확인한다.

## 테스트

- 숫자 정규화와 후보 추출 단위 테스트
- 일치, 불일치, 후보 없음 테스트
- 경로 순회와 이미지 외 파일 거부 테스트
- 관리자 인증이 없는 API 요청 거부 테스트
- 관리자 모달 버튼과 세 결과 상태 렌더링 테스트
- 기존 계좌 검증, 승인, 반려 흐름 회귀 테스트

## 성공 기준

관리자가 다른 PC에서 관리자 페이지에 로그인한 뒤 버튼 한 번으로 증빙의 계좌번호 후보와 등록번호의 일치 여부를 볼 수 있고, OCR 실패 시에도 기존 수동 검증 흐름을 그대로 사용할 수 있다.
