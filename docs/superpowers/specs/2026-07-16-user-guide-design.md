# EatsPay 화면 중심 이용가이드 디자인

## 결정

2026-07-16 사용자 검토에서 **B 방향: 화면 중심 매뉴얼**을 최종 선택했다. 실제 화면 캡처를 가장 큰 시각 요소로 두고, 화면 순서와 행동 설명은 보조 정보로 배치한다.

검토한 대안은 다음과 같다.

- A 빠른 검색형: 기능명을 아는 사용자가 빠르지만 일반적인 도움말과 차별성이 약하다.
- B 화면 중심 매뉴얼: 실제 앱·관리자 화면을 보면서 그대로 따라 할 수 있어 가장 명확하다.
- C 목적별 허브: 초보자에게 친절하지만 상세 화면까지 한 단계 더 거쳐야 한다.

## 목표와 대상

- 사용자 앱: 고객센터에서 로그인, 가입, 홈, 결제·충전, 카드, 가상계좌, 내 정보, 고객센터, 이츠톡 등 사용자 화면 35개를 안내한다.
- 대리점 관리자: `도움말 > 사용 가이드`에서 대시보드, 결제 내역, 대리점 정산, 가맹점 목록, 가맹점 상세, 내 가입 URL 6개 화면을 안내한다.
- 본사·총괄·운영·정산·고객 관리자에게 대리점 가이드 메뉴를 노출하지 않는다.
- 가이드 확인 중 실제 결제, 충전, 입금, 저장, 업로드, 알림 발송을 실행하지 않는다.

## 디자인 근거

- 프로젝트 `design.md`와 `docs/ui-consistency-directive.md`를 우선한다.
- 기본 폰트는 Pretendard, 앱 강조색은 `#03C75A`, 관리자 강조색은 `#3D9B35`, 기본 라운드는 8px를 유지한다.
- Refero의 Wise 스타일에서 차용한 원칙은 진한 녹색을 구조적 기준점으로 쓰고 밝은 녹색을 선택·진행 상태에 제한하는 것이다. Wise의 브랜드 자산, 폰트, 특유의 pill 형태는 복제하지 않는다.
- 지정된 Obsidian `90-MOC/디자인 시스템 지식 지도.md`는 현재 연결된 보관함에서 발견하지 못했다. 프로젝트 내부 디자인 문서와 기존 EatsPay 앱·관리자 화면을 최종 기준으로 사용한다.

## 시각 체계

### 색상

- Primary action: `#03C75A`
- Structural dark: `#163300`
- Admin primary: `#3D9B35`
- Text: `#121712`
- Secondary text: `#687269`
- Border: `#D9E5D8`
- Quiet surface: `#F3F7F2`
- Canvas: `#FFFFFF`

초록색은 활성 화면, 단계 번호, 선택 상태에만 사용한다. 카드 전체를 초록색으로 채우거나 장식용 그라디언트와 과한 그림자를 사용하지 않는다.

### 타이포그래피와 간격

- 화면 제목: Pretendard 700, 모바일 22px, 관리자 24px
- 항목 제목: Pretendard 700, 16–18px
- 본문: Pretendard 400–500, 13–15px
- 보조 라벨: Pretendard 700, 10–12px
- 간격은 4px 단위를 사용하고 주요 패널 안쪽 여백은 모바일 16px, 관리자 18–24px로 둔다.

### 시그니처 요소

실제 캡처와 연동되는 **화면 인덱스 레일**을 사용한다. `09 / 35`, `01 / 06`처럼 현재 위치를 명확히 표시하며 장식 번호가 아니라 실제 탐색 순서를 뜻한다.

## 사용자 앱 구조

사용자 가이드는 기존 `고객센터 > 이용가이드` 화면 안에서 동작한다.

1. 기존 앱 상단바: 이전, EatsPay 로고
2. 페이지 제목과 한 줄 설명
3. 검색창
4. 가로 스크롤 카테고리
5. 선택한 화면 제목과 `현재 / 전체` 인덱스
6. 430px 기준 실제 화면 캡처
7. 캡처 아래 단계별 행동 설명

초기 진입에서는 첫 화면을 바로 선택해 빈 목록 페이지를 만들지 않는다. 이전·다음 화면 이동과 검색 결과 선택은 같은 상세 영역을 갱신한다. 하단 내비게이션과 콘텐츠가 겹치지 않도록 기존 안전 여백을 유지한다.

## 대리점 관리자 구조

기존 관리자 좌측 내비게이션은 변경하지 않고 `도움말 > 사용 가이드` 선택 상태만 유지한다. 콘텐츠 영역은 세 부분으로 나눈다.

1. 왼쪽 화면 인덱스 레일: 6개 업무 화면
2. 중앙 화면 무대: 선택한 관리자 캡처와 화면명
3. 오른쪽 단계 패널: 해당 화면에서 확인하거나 처리할 순서

화면 폭이 줄면 단계 패널을 캡처 아래로 이동한다. 대리점 화면 목록은 6개로 고정하며 다른 관리자 권한의 화면이나 데이터를 섞지 않는다.

## 상호작용

- 검색은 제목, 요약, 카테고리, 키워드에 적용한다.
- 카테고리를 바꾸면 해당 범위의 첫 결과를 자동 선택한다.
- 화면 인덱스를 선택하면 캡처, 제목, 설명, 단계가 한 번에 바뀐다.
- 현재 선택 항목에는 `aria-current="page"`를 적용한다.
- 키보드 포커스는 2px 녹색 외곽선으로 표시한다.
- 이미지 로딩 실패 시 빈 프레임 대신 `화면 캡처를 불러오지 못했습니다`와 다시 시도 안내를 표시한다.
- 검색 결과가 없으면 검색어 초기화 버튼과 사용 가능한 카테고리를 안내한다.
- 새 인라인 `style`과 새 인라인 `onclick`을 추가하지 않고 기존 이벤트 위임을 유지한다.

## 반응형 기준

- 사용자 앱: 360–430px에서 가로 넘침이 없어야 한다.
- 대리점 관리자: 1280px 이상에서는 3열, 900–1279px에서는 인덱스+본문 2열과 하단 단계, 899px 이하에서는 단일 열로 표시한다.
- 캡처는 원본 비율을 유지하고 잘라내지 않는다. 썸네일은 보조 탐색에만 사용한다.
- `prefers-reduced-motion`에서 전환 애니메이션을 제거한다.

## 데이터와 컴포넌트 경계

- `guide-data.js`: 화면 메타데이터와 단계만 관리한다.
- `guide-renderer.js`: 대상 필터, 검색, 선택 상태, 접근성 속성, 마크업을 관리한다.
- `user-guide.css`: 공통 시각 체계와 반응형 구조를 관리한다.
- 사용자 앱과 관리자 래퍼는 audience와 마운트 위치만 전달한다.
- 기존 캡처 41개와 마스킹 규칙을 그대로 승계한다.

## 검증 기준

- 사용자 35개, 대리점 6개가 서로 섞이지 않는다.
- 초기 진입과 화면 선택 후 상세 화면은 항상 정확히 1개만 표시된다.
- 검색, 카테고리, 이전·다음, 이미지 오류, 빈 결과 상태를 테스트한다.
- 모바일 430px과 관리자 1440px에서 실제 캡처를 남겨 레이아웃을 검토한다.
- `node --check`, 관련 Node 테스트, `npm run check:ui`, 브라우저 클릭 검증을 통과한다.
- 운영 배포 전 로컬 캡처를 사용자에게 먼저 보여주며, 승인 없이 운영에 반영하지 않는다.
